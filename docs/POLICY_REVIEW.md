# Activating a real scheme

The three bundled real entries are deliberately drafts. A dated official summary is evidence of some conditions, not proof of complete eligibility or an open application window.

1. Obtain the responsible department's current governing order, amendments, detailed scheme instructions and applicable year/cycle. Record publication, effective and retrieval dates separately.
2. Compare them with the current source seed. Add any additional official sources and their immutable snapshots through the catalogue/source ingestion code. The UI presently reviews existing sources; it does not accept arbitrary ingestion URLs.
3. Enumerate all relevant inclusions, exclusions, exceptions, units, age cutoffs, schooling continuity, income definition/period, residency, course/college restrictions, benefit incompatibilities, renewal rules and required verification stages. Confirm documents from the responsible authority.
4. Encode conditions using the small typed rule language. Every leaf requires an existing source ID and a specific section/page. An incomplete group must not be labelled complete. If a condition cannot be represented in the current schema, extend the fields/rule operators and add independent tests before activation.
5. Build test profiles with expected decisions established separately from the implementation. Test exact thresholds, missing values, exceptions, stale dates and contradictory evidence. Have a knowledgeable person review the original-language policy and Tamil explanations.
6. In Sources & review, paste the reconciled rule, record the evidence and limitations, set verified window dates, and attest complete coverage only if established. Rules are versioned and review lasts 30 days. Daily source changes flag review earlier.
7. Run a fresh assessment. Government authorities still decide the actual application outcome.

The review UI is for the owner of this local development pilot. It is not a role-separated institutional approval system. Do not use the checkbox simply to make automation run. For a new scheme, preserve a reviewer record with identity, scope, checked source hashes and an independently validated case set.

A candidate can pass the known summary conditions and still receive REVIEW_REQUIRED. Unknown information is not a failed criterion. A current MATCH does not mean applications are open, documents are valid, funds are available or a benefit will be approved.


From 1.0.3, a preliminary match with saved profile details and complete configured documents can start form preparation when the window is unknown. Policy review remains necessary for final submission. Completing the profile or uploading documents does not change policy-review records. A known failed condition or missing fact is now displayed separately from pending policy review.
